# 🛰️ P2P Decentralized Storage Network

This is a mini-project for CSC196D demonstrating decentralized file storaging utilizing Ethereum smart contracts, peer-to-peer (P2P) storage nodes, coordinator backend, and modern Web3 UI.
This is a simulation of how major platforms such as Filecoin index their files on-chain but store actual file off-chain across nodes.

---

# 🚀 Features

### 🔗 1. Blockchain File Registry
- Stores and verifies:
  - File owner  
  - File hash  
  - File size  
  - Storage node replicas  
- Guarantees integrity and tamper resistance.

### 📦 2. Peer-to-Peer Storage Nodes
Each node:
- Accepts uploaded file data  
- Stores files locally  
- Exposes HTTP APIs for retrieval  
- Is registered on-chain with node ID + URL  

Nodes run locally at:
- Node 1 → http://localhost:4001  
- Node 2 → http://localhost:4002  

### 🧠 3. Coordinator Backend
- Accepts file uploads from UI  
- Replicates files to all storage nodes  
- Registers file metadata on blockchain  
- Serves metadata to UI  
- Automatically registers storage nodes on startup  

Frontend served at:

```
http://localhost:5000/
```

# 🛠️ Installation & Setup

## 1️⃣ Install dependencies
```bash
npm install
```

## 2️⃣ Start Ganache (local Ethereum chain)
In a new terminal:
```bash
npx ganache
```

Keep this running.

## 3️⃣ Compile + Deploy smart contracts
```bash
cd ~/p2p-storage
truffle migrate --network development --reset
```

## 4️⃣ Start Storage Nodes
### Terminal 1 – Node 1:
```bash
node storage-nodes/node1/server.js
```

### Terminal 2 – Node 2:
```bash
node storage-nodes/node2/server.js
```

## 5️⃣ Start Backend API + Serve UI
### Terminal 3:
```bash
node backend/server.js
```

You should see logs confirming:
- Contract address
- Node auto-registration  
- Backend running on port 5000

# 🖥️ Using the Web UI

Open in browser:

```
http://localhost:5000/
```

### Upload a file
- Enter a Ganache account address  
- Choose a file  
- Click **Upload**  

The system will:
- Hash the file  
- Store it on Node1 + Node2  
- Register metadata on-chain  
- Display fileId, hash, size, replicas  

### View blockchain metadata
UI shows JSON:
```json
{
  "owner": "0x...",
  "fileHash": "0x123...",
  "size": 42,
  "replicas": ["0xNODE1", "0xNODE2"]
}
```

### View replica nodes
Shows:
- Node ID  
- Node URL  
- Active status  
- Download links  

### Download from any node
Example:
```
Download from Node 1 (http://localhost:4001)
Download from Node 2 (http://localhost:4002)
```

# 🧱 Smart Contract Overview

### StorageRegistry.sol

Tracks:

| Field | Description |
|-------|-------------|
| owner | Uploader address |
| fileHash | keccak256 of file data |
| size | File size in bytes |
| replicas[] | Storage node IDs |

Key functions:
```solidity
registerNode(nodeId, url)
registerFile(fileId, fileHash, size, replicas)
getFile(fileId)
getNode(nodeId)
```

FileId is computed:

```
fileId = keccak256(fileHash + ownerAddress)
```

---

# 🧬 Replication Flow

1. UI sends file → backend  
2. Backend stores temporary file  
3. Backend uploads to each node  
4. Nodes store binary data  
5. Backend registers metadata on the blockchain  
6. UI can fetch metadata or download from any node  

If one node goes down → the other still serves the file.
